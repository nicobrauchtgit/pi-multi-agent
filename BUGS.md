# Bug tracker

Confirmed issues found during implementation and review are recorded here. Blocking defects are fixed in the current task; valid deferred work remains listed until resolved.

## Open bugs

- **C1-REG-001 — Workflow transcript artifacts now contain manager UI previews, not the legacy runner's fuller tool payloads:** Manager-backed workflow transcripts intentionally project normalized `argsPreview`/`outputPreview` fields. For Pi tools this can reduce arguments to roughly 4 KiB and results to the first non-empty line. D4 may persist a protected redacted artifact outside SQLite when full recovery is required, but SQLite retains only bounded excerpts and artifact metadata/references; current `transcripts.json` must not be described as full-fidelity.
- **C1-REG-002 — Oversized explicit workflow results degrade to a whole-result truncation stub:** Core `workflow.json` state now degrades per field and preserves run/agent identity, but an explicit script return above the 1 MiB `result.json` bound is still replaced by the serialization truncation object. D4 should store redacted result artifacts with per-field or content-aware degradation while preserving a stable artifact envelope.

## D5 headline item

- **OBS-D5-001 — Observability daemon must become project-scoped (one daemon+port per project, not one global per agent-home):** The companion daemon currently binds a single ephemeral loopback port per `--agent-dir` (`~/.pi/agent`), which is shared across ALL projects. Run data from every repo funnels into one SQLite store and one port, so working across multiple projects (or running a second daemon) causes home/lock/state/port contention — "two servers" fighting over one home. D5 should re-architect this so each project gets its own daemon home and port, with a reliable right-port-to-right-project mapping (a per-project registry), or otherwise eliminate the possibility of two servers contending. This is the primary D5 hardening work and gets its own architecture pass (decided with the user 2026-08-24).

## D4 acceptance follow-ups (non-blocking; candidates for D5 hardening)

- **OBS-D-012 — Artifact reference metadata is never persisted, making purge/UI reference paths dead:** The metadata ceiling in `companion/src/ingest/normalize.mjs` (~line 133) drops `canonicalPath`/`sourceKind`/`boundedPreview` in both policy modes, and `contentHash` is additionally destroyed by the `HEX_SECRET` rule (to `[REDACTED:token]`) even in rich mode. As a result purge's `artifactPathsByRun` (`maintenance-purge.mjs`) and the `ui/app.js` artifact-reference display are permanently empty. D5 should persist bounded artifact reference metadata (canonical path, sourceKind, size, non-secret content hash form) without reintroducing a secret-leak path — e.g. a hash representation that survives redaction like the 32-hyphen-32 eventId form.
- **OBS-D-013 — `writeRunArtifact` has no production callers and its kind is not in the reconciler allowlist:** The `workflow-state.json` artifact kind produced by `writeRunArtifact` is never written by production code and would not be imported by the reconciler allowlist even if it were. Either wire it end-to-end (writer → allowlist → reconcile) or remove it in D5; do not leave a half-connected path.
- **OBS-D-014 — Artifact projection can set `settled_at_ms` on a still-running run:** `companion/src/project/artifact-projection.mjs` (~lines 199-212) may write `settled_at_ms` even when the primary run status is `running`. Projection precedence must never let a lower-precedence artifact fact imply settlement of a run the primary lifecycle says is still running.
- **OBS-D-015 — Canonicalization form mismatch (realpath vs resolve) can defeat purge scope matching on macOS:** Reconcile uses `fs.realpathSync.native` for allowed candidates but `path.resolve` for symlinked/skipped candidates, and `markPurged`'s root-scope match can therefore never match on macOS `/private` aliasing. Unify canonical-path derivation so purge scope, reconcile state keys, and tombstone lookups always agree. (Partially addressed by the B1 repair; audit the remaining call sites in D5.)
- **OBS-D-016 — Dead code in reconcile/purge (PARTIALLY RESOLVED; two claims were wrong):** Re-audited during the `.mjs`→`.ts` port. Resolved: `pathWithin` (defined and exported in `maintenance-purge.mjs` with zero call sites) is removed, and the discarded `processIsAlive(error.owner.pid)` no-op at the `LockHeldError` branch is removed along with its now-unused import (`process.kill(pid, 0)` is a pure liveness probe, so the call had no effect). Corrections to the original entry: `inspectOptional` is **not** unused — `reconcile.mjs` calls it in `scanRoot`; and `reconcileOnce` is **not** dead — it is the reconciler's main entry point, used by `createReconciler` and ~20 test call sites. What is true about `reconcileOnce` is narrower and remains open: it returns a hardcoded `imported: 0` alongside genuine `scanned`/`totalBytes`/`capped` counters, so the `imported` field is permanently a lie. Fix the field or drop it in D5.

## Found during the TypeScript port (2026-08-24)

All verified independently against `git show HEAD` and reproduced; none introduced by the port.

- **OBS-P-001 — Relative `--agent-dir` produces a cwd-dependent protected-path inventory:** `companion/src/cli.mjs` assigns `--agent-dir` straight from argv with no `resolveAgentDir()`/`path.resolve()` (unlike the default path, which does). `observabilityPaths()` stores `agentDir` verbatim while `path.join`-ing the other 21 members, so a relative value yields a fully relative inventory (reproduced with `observabilityPaths("relative/trailing/")`). `child-session.ts` builds the child deny-list from it. Roots are canonicalized, but canonicalizing a relative path is cwd-dependent, and the daemon is spawned with cwd=repo-root while children run in the project cwd. Operator misconfiguration rather than attacker input, so a silent defense-in-depth gap, not a bypass. Resolve at the CLI boundary and/or normalize `agentDir` in `observabilityPaths()`.
- **OBS-P-002 — Invalid `contentMode` is accepted and fails OPEN to `rich`:** `contentMode()` validates with `value in CONTENT_MODE_RANK` against a plain object literal, so inherited `Object.prototype` keys pass. Verified accepted: `toString`, `constructor`, `hasOwnProperty`, `valueOf`, `__proto__`. `minimumContentMode("toString","toString")` then yields `"rich"` — the most permissive mode — instead of rejecting or failing closed. Mitigated because the daemon's independent metadata cap still narrows it (`minimumContentMode("toString","metadata") === "metadata"`), so this is a fail-open validation bug rather than an active leak. Fix with `Object.create(null)` or `Object.hasOwn`.
- **OBS-P-003 — `localeCompare` used for key ordering in four places:** `redaction.ts:340`, `normalize.ts:474`, `normalize.ts:517`, `policy.ts:304`. `localeCompare` is locale/ICU-sensitive and is not codepoint order (`_x,a,A,b,B,e,é,Z` vs `A,B,Z,_x,a,b,e,é`). **The idempotency fingerprint is NOT affected** — `canonicalize()` uses a bare `.sort()`, so `payload_sha256` is stable across hosts. The impact is limited to stored key ordering and to `redactJson`'s JSDoc claim of a "stable persisted representation", which is inaccurate as written. Low severity.
- **OBS-P-004 — Unterminated PEM discards the remainder of the input:** in `redactPrivateKeys`, a BEGIN marker with no matching END sets the cursor to end-of-input, dropping everything after it. Fail-safe (over-redacts) but silent and uncounted; the `<96` label guard can also swallow an interleaved short `BEGIN PUBLIC KEY` block.
- **OBS-P-005 — `normalizePolicyConfig` throws an uncoded `TypeError`:** `JSON.stringify(undefined)` returns `undefined`, so `Buffer.byteLength(undefined)` throws `ERR_INVALID_ARG_TYPE`; a circular object throws with `code === undefined`. Callers branching on `error.code` (the `producer-config.ts` fail-closed path) get nothing to match.
- **OBS-P-006 — `boundEncodedString` can drop redaction provenance:** when the marker-preservation branch cannot fit the suffix within `maximum`, it returns the partial-marker-trimmed `best` with no re-append, so the fact that a redaction occurred is lost while `truncated: true` is still reported.
- **OBS-P-008 — `NormalizedObservabilityEvent` and `ObservabilityEvent` disagree with each other and with the runtime:** `normalize.ts` declares `schemaVersion: 1`, `producer.kind: "pi"`, and a required `occurredAt: number`. The runtime accepts any safe integer `schemaVersion >= 1` (verified: returns `7`), a bounded opaque `producer.kind` (verified: returns `"codex"`), and omits `occurredAt` entirely when absent. The architecture doc supports the runtime on two of these — §7.1 says `schemaVersion` versions one event kind, and `occurredAt` is "optional display/provenance data". However, `ObservabilityEvent` in `events.ts` pins the same three fields, and _its_ narrowness is accurate: the producer factory (`events.ts` ~line 415) always sets `schemaVersion` to the constant and defaults `occurredAt` to `Date.now()`. The two types model different trust domains — producer-emitted vs. normalizer output over untrusted input — and `producer-sink.ts:406` assigns one to the other, silently bridging them. Widening `normalize.ts` alone does not typecheck. Resolving this means either splitting the types by trust domain or narrowing at the boundary with a runtime check; it is an event-contract decision, deliberately not made inside the mechanical port. Zero runtime impact today (types are fully erased).
- **OBS-P-007 — `BEARER` rule hardcodes its marker string:** it uses the literal `"Bearer [REDACTED:header]"` rather than composing from `REDACTION_MARKERS.header`, so changing that constant leaves this rule out of sync. Cosmetic.

## Deferred implementation work

- **TASK-D-001 — Durable structured-result artifacts:** Task B exposes validated structured results through live snapshots and tool/result delivery. Persisting protected redacted results outside SQLite, linking role records to the latest artifact, and storing only bounded preview/reference metadata in SQLite remains part of Task D4.
- **OBS-D-001 — Existing workflow artifacts are not secret-redacted:** `extensions/workflows/artifacts.ts` bounds transcripts/results, and `serialization.ts` writes them atomically, but neither applies secret redaction. Observability reconciliation must re-redact imports, and new shared artifacts must use the common scrubber; it must not create another unredacted copy.
- **OBS-D-003 — Shared-worktree changes cannot be attributed exactly:** Standalone and workflow children normally share cwd, and current manager/workflow events do not capture an isolated before/after patch. Any future v1 change summary must remain `shared/unattributed`; exact attribution is deferred until isolation or another non-racy ownership boundary exists.
- **OBS-D-007 — Unrestricted same-UID children can tamper with observability storage:** Pi/Claude shell tools and current Codex `danger-full-access` can create forged producer segments, delete backlog, or flood spool/quarantine as the parent user. D2's supported Pi/Claude file-tool guards now cover explicit paths, tool-specific globs, implicit cwd, and unsafe child working directories, but they are defense in depth rather than an OS integrity boundary. Production rich capture remains disabled; preventing same-UID write/forge attacks requires a real backend sandbox or separate OS identity and is not claimed by D2.
- **OBS-D-008 — Unicode-confusable secret spellings are outside the fixed scanner:** ASCII `.netrc` whitespace assignments are now covered, but fullwidth/confusable variants and tokens split with zero-width characters are not guaranteed matches. Metadata-only production capture limits exposure; rich capture must not be enabled until the redaction gate either covers or explicitly accepts a reviewed Unicode corpus.
- **OBS-D-010 — Browser fragment/opener exposure remains inside the accepted same-UID boundary:** D3 removes the read capability with `history.replaceState` before making API requests and never stores it in DOM, cookies, web storage, logs, or request URLs. A browser may nevertheless retain the pre-replacement navigation in profile/history internals, Chrome DevTools may display the original fragment-bearing navigation URL even though the HTTP request target sent to the daemon has no fragment, and the platform opener briefly receives the fragment URL in argv where another same-UID process could inspect it. The capability is loopback/Host-bound, read-only, separately scoped, and rotated on every daemon restart, but eliminating these residuals would require a separately designed bootstrap exchange or stronger OS identity boundary. This is not claimed solved by D3.
- **OBS-D-011 — Runs pagination intentionally has no D3-specific order index:** D3 caps the keyset query at 200 rows and orders deterministically by `(last_seq DESC, run_id DESC)` on the frozen v1 schema. Existing project/status indexes order by producer time and do not satisfy that receive-sequence order, so `EXPLAIN QUERY PLAN` may show a bounded scan/temp sort for the run list while scoped event routes demonstrably use `events_run_seq` and `events_agent_seq`. Add or remove an index only in D5 after dogfood measurements show a real latency/storage trade-off.
- **TASK-E-001 — Structured status in supervisor UI:** The `/subagents` dashboard does not yet show a dedicated structured-output success/failure badge. This remains optional Task E UX work; schema failures are already visible through normal error text and tool details.

## Planning/tooling lessons

- **TOOLING-001 — Large inline workflow handoffs can exceed the agent-request limit:** Workflow `wf_275662319c63` completed seven inventory/architecture/review agents, then failed in the Document phase with `Workflow sandbox sent an invalid agent request` after the script concatenated the full architecture output and all review data into one author prompt. ## Resolved during Task D2

- **OBS-D-002 — Child observability path boundary:** Added one canonical realpath-aware protected inventory for the companion root (token/DB/WAL/SHM/state/lock/spool/config/log/export), roles, workflow artifacts, future run artifacts, and configured Moshi paths.
